    The transaction

    What a valid result proves

    • The named transaction pays the shown value to the shown recipient with the shown memo. This is recovered cryptographically from the transaction with the per-output key in the receipt.
    • If signed: the holder of the shown issuer key made this receipt and wrote its label.

    What it does not prove

    • Who is showing you the receipt, unless it is bound to a challenge you sent.
    • Which organisation holds the issuer key, unless the key id names a domain and that domain lists the key when you check it; even then, it vouches for the key now, not for when the receipt was made.
    • That the output is still unspent, or that whoever shows you the receipt can spend it: it shows a payment was made, not what happened to it since, and it carries no spending ability.
    • How deep the transaction is when it was loaded from a file. A node's count of confirmations is that node's view; for funds that matter, check your own node.
    • Anything about other outputs, other transactions or balances.

    Privacy: this page makes a request outside this site only when you ask. The transaction lookup tells the node which transaction you looked up. The issuer check tells the named domain that one of its receipts is being checked. The page stores nothing.
